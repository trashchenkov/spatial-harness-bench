# Spatial Harness Bench

[Лидерборд на GitHub Pages](https://krestnikov.org/spatial-harness-bench/) · [Таблица в репозитории](LEADERBOARD.md)

Бенчмарк проверяет пространственное мышление моделей и харнесов на текстовых описаниях и векторной графике.

The project follows the structure of [Harness Bench Fast](https://github.com/ai-forever/harness-bench-fast), with separate task definitions, verifiers, and runners.

## Что измеряет каждая задача

В лидерборде модели отсортированы по [общей оценке](#общая-оценка). У каждой задачи свой проверяющий модуль.

| Задача | Ось | Основная метрика | Рекомендуемый режим для сравнения моделей |
| --- | --- | --- | --- |
| [01 · ASCII-рисунки](#01--узнай-свои-ascii-рисунки) | Кодирование формы в текст и обратное распознавание | Узнанные рисунки, 0–10 | `--objects assigned` |
| [02 · Лабиринт](#02--найди-выход-из-лабиринта) | Построение карты по локальным наблюдениям, память | Найденные выходы, 0–10, и эффективность | `--suite` (версия 2) |
| [03 · SVG-рисунки](#03--узнай-свои-svg-рисунки) | Кодирование формы в SVG; ментальные перестановки на поле | Узнанные рисунки или верные клетки, 0–10 | `--objects assigned` или `kitchen`; `--difficulty expert`/`master` |
| [04 · Вопросы по SVG-сценам](#04--вопросы-по-svg-сценам) | Понимание сцены: счёт, перекрытия, трассировка, повороты | Верные ответы | `--set generated` с закрытым seed |
| [05 · Монтажный индекс](#05--монтажный-индекс) | Построение индекса игрового реплея и запросы по диапазону | Точный индекс и все 12 запросов, 0–1 | Изолированная сессия с движком и реплеем |
| [06–10 · Поэтажные планы](#building) | Совмещение этажей, зеркальная ориентация, выбор трассы | Пять отдельно проверяемых ответов, 0–5 | Одна новая сессия на задачу |
| [AD&DBench](#adnd) | Маршруты с весами, память и исследование мира | Четыре карты, поручение и экспедиция, 0–6 | Общие для всех моделей карты и эпизоды |

Одиночный прогон из десяти пунктов даёт 95% интервал шириной около ±3 балла. Для сравнения моделей делайте несколько повторов с разными seed и сводите их командой из раздела [Повторы и доверительные интервалы](#повторы-и-доверительные-интервалы).

### Общая оценка

Итоговая шкала — от 0 до 100. Первые четыре блока дают до 22 баллов каждый, суммарно до 88. Аркадная задача добавляет 1 балл за прохождение проверки и 0 при ошибке. За каждый из пяти планов дома, четырёх взвешенных маршрутов, поручения на память и экспедиции даётся ещё по 1 баллу. В первых четырёх блоках балл каждого режима делится на его максимум, затем доли усредняются внутри блока. Для ASCII учитываются назначенные и свободно выбранные предметы. Для лабиринтов берётся доля пройденных карт из десяти. Для собственных SVG учитываются четыре уровня сложности, для готовых сцен — публичный и закрытый наборы. В обеих SVG-задачах учитываются ответы по исходному коду. Общий балл вычисляется по исходным результатам с округлением только в конце.

В лидерборде для каждой модели использован один зачётный прогон каждой конфигурации. Все модели получили одинаковые наборы сцен и карты. Для распознавания используется штатный пакетный режим. Если модель исчерпала лимит вывода Claude Code, проверяется файл, который она успела сдать. Пустые ответы получают ноль. При сбое транспорта прогон восстанавливается до публикации. При одинаковом опубликованном балле модели делят место. Для GigaChat-4 задачи 01–05 измерены на Pi 0.73.1, планы дома и AD&DBench — на Pi 1.6.0.

#### Ограничения прогона

Для задач 01–10 действует лимит шагов агента. В интерактивных задачах AD&DBench раннер также ограничивает ожидание ответа на ход. Для Claude Code применяются следующие настройки:

- Сессия идёт не дольше 100 ходов агента (`--max-turns`, переменная `SPATIAL_MAX_TURNS`). Если лимит исчерпан, проверяется уже сданный файл.
- Лимит вывода одного ответа выставлен на максимум, который принимает Claude Code: `CLAUDE_CODE_MAX_OUTPUT_TOKENS=128000`. Большие значения Claude Code урезает до 128 000.

В лабиринте на всю карту даётся два решения на комнату. Pi и штатный chat-адаптер дают до **32 ответов модели на выбор одного направления**. Один ответ может содержать несколько вызовов инструментов. Направление, сданное в 32-м ответе, принимается. Если этот ответ снова запрашивает инструменты, карта получает 0 баллов, и серия переходит к следующей. При новом ходе счётчик начинается с нуля.

#### Настройка размышлений

По умолчанию модель работает на среднем уровне размышлений, если модель и харнес позволяют его задать. В Claude Code это `--effort medium`, в Codex — `model_reasoning_effort="medium"`, в Chat Completions — `reasoning_effort: "medium"`. Уровень один для всех задач и режимов прогона. Для GigaChat-4 через Pi задан профиль `high` с лимитом вывода 65 536 токенов на ответ.

Если уровень задать нельзя, модель работает с настройкой харнеса по умолчанию. Свой бюджет размышлений вместо уровня не подбирается. В локальном отчёте записываются запрошенный уровень и параметры, которые реально ушли в API. Например, Claude Code 2.1.278 не передаёт `effort` моделям, которых нет в его каталоге, и отправляет им фиксированный бюджет `thinking.budget_tokens` на весь лимит вывода. Такой прогон помечается как выполненный без настройки уровня.

Для обновления таблицы выполните `python3 scripts/score_leaderboard.py ПОЛНЫЙ_ОТЧЁТ docs/results/ИМЯ.json`, затем `python3 scripts/render_leaderboard.py`. Полный отчёт хранится в локальном каталоге прогона.

### Установка

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/). Морфологический словарь pymorphy3 входит в основные зависимости. Задачи 03 и 04 дополнительно требуют extra `svg`, библиотеку Cairo и Tesseract с языками `rus` и `eng`. На Debian/Ubuntu это пакеты `libcairo2`, `tesseract-ocr`, `tesseract-ocr-rus` и `tesseract-ocr-eng`. Полный набор тестов запускается командой `uv run --extra svg python -m unittest discover -s tests -v`.

### Общий запуск из CLI

```bash
# План без Docker и без обращения к модели (15 блоков при установленной геометрии)
uv run python -m spatial_harness_bench run --all \
  --agent opencode --model "$OPENCODE_MODEL" --dry-run

# Малый проверочный прогон на OpenCode
uv run --extra svg python -m spatial_harness_bench run \
  --select building,svg_scenes.generated,adnd_expedition --smoke \
  --agent opencode --model "$OPENCODE_MODEL" --image "$AGENT_IMAGE" \
  --network "$AGENT_NETWORK" --output runs/opencode-smoke

# Другой CLI: передайте команду внутри образа, аргументы после --
uv run python -m spatial_harness_bench run --select building \
  --image "$AGENT_IMAGE" --output runs/custom -- my-agent --batch
```

`--all` запускает все семейства из текущей установки. Для SVG Recall в него входят
четыре уровня, для ASCII Recall — свободный и назначенный наборы, для SVG Scenes —
фиксированный и сгенерированный. `--select` принимает имена семейств и отдельных
блоков через запятую; полный список показывает `--dry-run`. Если установлено семейство
Engineering Geometry, общий прогон включает 30 его заданий. `--smoke` сокращает
Building и Maze до одного задания, уменьшается число сгенерированных SVG Scenes,
AD&D Expedition ограничивается двумя ходами, а Engineering Geometry — одним
примером добавления жилы. Остальные блоки не меняются. Smoke — не зачётный профиль.
Для повторяемого отладочного запуска укажите общий публичный `--seed`; не
передавайте через него приватные seed зачётных прогонов.

Режимы подключения:

- **Файлы:** любой неинтерактивный CLI, который принимает UTF-8 из stdin и пишет
  артефакты в текущую папку. Встроены команды запуска для Codex, OpenCode и Pi.
- **SVG как текст:** профили Codex, OpenCode и Pi передают
  исходный SVG в сообщении, не монтируют рабочие файлы и проверяют, что CLI не
  вызывал инструментов.
- **Сессии:** одна нативная сессия с полной историей на эпизод Maze, AD&D Memory или
  AD&D Expedition. Pi использует штатные RPC-мосты с инструментами заметок в Maze
  и Expedition; в Memory и у профилей Codex/OpenCode игровые инструменты отключены.
  Если CLI не поддерживает нужный режим, план отклоняется до запуска;
  переключения на прямой вызов модели нет.

Образ задаётся через `--image` или `SPATIAL_AGENT_IMAGE`. Это уже собранный
**локальный** Linux-образ с нужным CLI и заранее настроенным провайдером.
Для нативных SVG и сессий также нужен `python3` внутри образа. Встроенный
профиль OpenCode проверен с версией 2.0.20: для SVG и сессий в его конфигурации
должен быть primary-агент `svg-source` с запретом всех инструментов
(`permissions: [{"action":"*","resource":"*","effect":"deny"}]`).
Codex должен иметь доступ к своей конфигурации и возможность писать историю
внутри контейнера для `exec resume`; проверенная версия — 0.172.0.
`--model` для OpenCode — селектор `provider/model` из конфигурации образа (для
Codex — ID модели). Для Pi 1.6.1 укажите `--agent pi --model provider/model`
из `models.json` образа. Если селектор — псевдоним, `--model-label` записывает
отдельно указанное оператором имя реально настроенной модели.
Внутри контейнера UID/GID — 65532, `HOME=/tmp`. Передача командной строки
не передаёт переменные окружения хоста. Не встраивайте секреты в образ.

Сеть по умолчанию отключена. Для настоящих моделей задайте `--network` (или
`SPATIAL_AGENT_NETWORK`), указывающий на выделенную **внутреннюю** Docker-сеть.
Подключайте только доверенный шлюз к выбранному провайдеру; ключи остаются
на стороне этого шлюза. Не подключайте сеть, в которой доступны эталоны,
логи других заданий, Docker API или файловая система хоста. Раннер не
монтирует репозиторий, домашний каталог и каталоги результатов. Для файлового
этапа он копирует только подготовленный публичный рабочий каталог и принимает
обратно только предусмотренные форматом файлы. Linux с Bubblewrap и системным
Python 3.12 по-прежнему нужен на стороне **верификатора** Arcade Clips.

В приватном `output/result.json` сохраняются агент, версия встроенного CLI, ID
образа, запрошенная модель и результаты блоков. Детальные результаты и логи
остаются в подкаталогах. `technical_error` означает, что блок не получил
оценку из-за сбоя; оценка 0 от верификатора — не технический сбой. Сводка
обновляется после каждого блока и не вычисляет новый балл лидерборда.
Если нативный харнес сообщил техническую причину (например, `turn_timeout` или
`provider_error`), сводка хранит её отдельно от балла. Для диагностики
сохраняются короткие коды и числовые HTTP-статусы, а не заголовки запросов.

Для общих CLI-адаптеров подробности каждой попытки лежат в
`attempts/<блок>/<id>/attempt.json`, а рядом — ограниченные по размеру
`stdout.log` и `stderr.log`, если был вывод. На SVG-этапе `stdout.log`
содержит ответ до разбора; при обрыве доступный текст нативного ответа
сохраняется в `partial-answer.txt`. Журнал фиксирует решение SVG-парсера,
в том числе старую подстановку пустых файлов при отклонённом JSON. Для игр
сохраняется доступный вывод транспорта; полный журнал вызовов API не ведётся.
При повторе предыдущая попытка не перезаписывается. Геометрия по-прежнему
сохраняет логи в каталоге каждого экземпляра.

Это приватные артефакты проверяющего, не вход агента и не публикация. Из новых
логов удаляются известные секреты из окружения и распространённые формы
заголовков авторизации; произвольный вывод CLI всё равно требует проверки
перед передачей третьим лицам. Лимит — 256 КиБ на поток, обрезка отмечается
в JSON. Баллы и правила проверки не меняются.


### Повтор при отказе шлюза

По умолчанию бенчмарк делает до трёх повторов после первого отказа, с паузами 1, 2 и 4 секунды. Переменная `SPATIAL_GATEWAY_RETRIES` задаёт число повторов. В файловых задачах повторяется только прерванный этап. Раннер восстанавливает исходные файлы и промпт этого этапа, включая рисунки или сцены для распознавания. Файлы, записанные до отказа в этой попытке, в оценку не входят.

Встроенный чат-адаптер лабиринта повторяет тот же HTTP-запрос вместе с историей и результатами инструментов. Ход засчитывается после получения команды. При обрыве стороннего адаптера раннер может заново начать текущую карту с тем же seed и лимитом ходов. Завершённые карты сохраняются.

Сторонний адаптер может сигнализировать об отказе шлюза кодом выхода `75` (`EX_TEMPFAIL`). Раннер также распознаёт диагностику HTTP и разрыва соединения у аварийно завершившихся адаптеров. После исчерпания повторов раннер выходит с ошибкой и записывает `status: "error"`, `reason: "gateway"` и `score: null` для затронутой задачи или режима. Такой результат исключается из подсчёта баллов. Обычный ответ модели, включая неверный или пустой, оценивается с первой попытки.

### Сравнение ответов

Все задачи сверяют ответ с эталоном одинаково (`spatial_harness_bench/answers.py`). Регистр, лишние пробелы, знаки по краям и различие «е/ё» не важны. Слова сравниваются по словарной лемме, поэтому «сиреневой» совпадает с «сиреневый», а «кошки» — с «кошка». Равнозначные названия одного объекта перечислены в [`synonyms.json`](spatial_harness_bench/synonyms.json): синонимы, разговорные и уменьшительные формы, например «кот / кошка», «ель / ёлка», «зонт / зонтик». Родовые понятия не объединяются: «ёлка» не засчитывается за «дерево». Пары набора `kitchen` намеренно лежат в разных группах. Версия правил записывается в отчёт в поле `matcher`.

## Задачи AD&DBench

Эти задачи дают до 6 баллов в общей оценке. В зачёт входят четыре карты на одном seed, поручение уровня `medium` с полной историей без заметок и экспедиция на 80 ходов с доступом к заметкам. В зачётной экспедиции на выбор действия отводится до 32 ответов модели и 1200 секунд. Все три набора используют детерминированную генерацию и проверку; результаты зависят от харнеса и правил передачи истории и не являются автоматически сопоставимыми с прежними прогонами AD&DBench.

| Задача | Что проверяется | Интерфейс и описание |
| --- | --- | --- |
| Взвешенный маршрут | Первый шаг маршрута минимальной стоимости по известной карте | [adnd_route](spatial_harness_bench/adnd_route/README.md) |
| Память о поручении | Вспомнить исходное поручение после отвлекающих встреч | [adnd_memory](spatial_harness_bench/adnd_memory/README.md) |
| Короткая экспедиция | Поручения и исследование в игре с частичными наблюдениями | [adnd_expedition](spatial_harness_bench/adnd_expedition/README.md) |

Для сопоставимых прогонов фиксируйте версию задачи, харнес, параметры модели, правила контекста и одинаковые seed. Результаты записываются локально; эти каталоги могут содержать seed, наблюдения и ответы, поэтому не публикуйте их целиком. Изоляция рабочей папки сама по себе не ограничивает доступ к другим файлам: при использовании shell харнес необходимо запускать в отдельной изоляции. Технические сбои учитываются отдельно от неверных ответов или завершённых игр.

Маршрутный набор содержит четыре задания на seed со сбалансированными ответами. При оценке неопределённости используйте независимые seed как единицы наблюдения: pooled Wilson в `stats` не учитывает зависимость заданий одного набора. Экспедиция и режимы памяти пока не откалиброваны на моделях; завершение или лимит в короткой игре нельзя считать общим рейтингом игрового мастерства.

## 01 · Узнай свои ASCII-рисунки

Модель рисует десять объектов в файлах `0.txt`–`9.txt` и записывает их названия по-русски в `desc.txt` в том же порядке. Раннер читает эталон в память, удаляет первую рабочую папку и запускает тот же харнес в новой папке. Во второй сессии модель получает десять пронумерованных файлов и восстанавливает `desc.txt`.

| Набор объектов | Кто выбирает | Что измеряется |
| --- | --- | --- |
| `free` (по умолчанию) | Модель сама выбирает объекты, которые сможет узнать | Кодирование вместе со стратегией выбора, которая позволяет взять лёгкие объекты |
| `assigned` | Раннер выбирает 10 из 40 объектов по seed (`spatial_harness_bench/objects.py`) | Только кодирование и распознавание. Одинаковый seed даёт всем моделям одинаковый список |

| Результат для рисунка | Баллы |
| --- | ---: |
| Подпись или название объекта в файле с графикой, при любом ответе | −1 |
| Название восстановлено на своей строке | +1 |
| Ошибка, пропуск, пустой или некорректный ASCII-рисунок | 0 |

Итог — сумма баллов с нижней границей 0 и максимумом 10. Ответ сверяется по правилам из раздела [Сравнение ответов](#сравнение-ответов). В наборе `free` эталонный `desc.txt` должен содержать десять непустых названий, различных по смыслу. Синонимы и уменьшительные формы считаются одним объектом, поэтому пара «ель» и «ёлка» — ошибка первого этапа. В наборе `assigned` эталоном служит назначенный список, а `desc.txt` художника не используется.

Проверка подписей работает **до распознавания**. Она ищет все эталонные названия, их синонимы и транслитерации в строках и столбцах, в том числе с разделителями. Проверка также помечает цепочки длиной от двух букв по горизонтали или от трёх по вертикали, если в цепочке есть разные буквы, и слова из трёх и более букв, записанные через одинаковый разделитель (пробел, точку, дефис или подчёркивание). Одиночные `o` и повторяющиеся штрихи вроде `ooo` допустимы. Сочетание разных букв может сработать и в роли штриха. Рисунок с нарушением заменяется для второй сессии пустым файлом на той же позиции, чтобы подпись не раскрыла ответы для других рисунков.

### Запуск

Из корня репозитория с настроенным харнесом, например Claude Code с `ANTHROPIC_API_KEY`:

```sh
uv run python -m spatial_harness_bench.ascii_recall --objects assigned --seed 1 \
  --output runs/attempt-01 -- \
  claude -p --bare --no-session-persistence --strict-mcp-config \
  --tools Read,Write --allowedTools Read,Write
```

После `--` можно указать другой харнес. Команда должна читать промпт в UTF-8 из stdin, работать с файлами текущей папки и при каждом запуске начинать новый диалог с той же моделью, без общей памяти и доступа к журналам предыдущей сессии. Для скрипта-адаптера используйте абсолютный путь. Раннер управляет процессами и рабочими каталогами. Настройки памяти и доступ к внешнему хранилищу контролирует адаптер харнеса.

В новом каталоге результата сохраняются исходные рисунки и эталон в `original/`, восстановленный `desc.txt` и `result.json` с ответом, баллом и причиной штрафа для каждой позиции. Для набора `assigned` в отчёт записываются `objects` и `seed`.

## 02 · Найди выход из лабиринта

В зачёт входят десять задач с идентификаторами от `02-maze-v2-01` до `02-maze-v2-10`. Модель начинает в одной из комнат и выигрывает, когда входит в комнату с выходом. Старт и выход различаются и могут находиться внутри сетки.

На каждом ходу модель получает текст о четырёх сторонах **только текущей комнаты** и выбирает одно направление. Вперёд всегда означает север, вправо — восток. Через открытую дверь можно пройти в обе стороны. Закрытая дверь и стена непроходимы. Ошибочная команда или попытка пройти через препятствие расходует решение и оставляет модель на месте. Модель может держать маршрут в контексте, вести журнал или рисовать свою карту в файле.

### Почему версия 2

Версия 1 строила лабиринт как остовное дерево. В дереве обход по одной стене проходит каждый коридор не больше двух раз, поэтому агент без памяти, который просто держится правой рукой за стену, находил выход на всех десяти уровнях: контрольный прогон `runs/maze-levels-01/right-hand` получил 10/10. Задача проверяла дисциплину, а не построение карты.

Версия 2 открывает дополнительные двери в 15% оставшихся внутренних стен, и в лабиринте появляются петли. Генератор принимает только такие карты, на которых **любой** обход по стене — правой или левой рукой, с любым начальным направлением — замыкается в цикл и не доходит до выхода. Чтобы выйти, агенту нужно помнить, где он уже был.

Лимит остаётся прежним: два решения на комнату. Обход в глубину с памятью делает не больше 2·(комнат − 1) переходов, поэтому агент с идеальной картой всегда укладывается в лимит. Более жёсткий лимит превратил бы задачу в лотерею порядка обхода.

### Метрики

Основной результат — найден ли выход. Дополнительно в `result.json` каждого уровня записываются:

| Поле | Смысл |
| --- | --- |
| `efficiency` | Кратчайший путь / число решений для решённого уровня, иначе 0. Значение 1.0 означает, что агент прошёл кратчайшим путём |
| `explore_steps` | Медиана переходов агента, обходящего в глубину с памятью, по всем 24 порядкам предпочтения направлений: стоимость поиска выхода на неизвестной карте |
| `explore_ratio` | Решения агента / `explore_steps`. Значение ниже 1 означает, что агент исследует экономнее обхода в глубину |
| `attempts`, `moves`, `visited`, `shortest` | Решения, успешные переходы, посещённые комнаты, длина кратчайшего пути |

В `suite.json` поле `score` (0–10) — число решённых уровней, `efficiency` — средняя эффективность по всем десяти.

### Десять уровней лабиринта

Генератор подбирает карту по двум измеримым признакам: длине кратчайшего пути и стоимости исследования `explore_steps`. Оба показателя строго возрастают от уровня к уровню при любом seed.

| Уровень | Сетка | Кратчайший путь, ходов | Исследование в глубину, ходов |
|---:|---:|---:|---:|
| 1 | 5×5 | 3–6 | 15–24 |
| 2 | 6×6 | 7–8 | 25–32 |
| 3 | 7×7 | 9–10 | 33–45 |
| 4 | 8×8 | 11–12 | 46–58 |
| 5 | 10×10 | 13–14 | 59–80 |
| 6 | 11×11 | 15–16 | 81–100 |
| 7 | 12×12 | 17–18 | 101–120 |
| 8 | 13×13 | 19–20 | 121–145 |
| 9 | 14×14 | 21–23 | 146–170 |
| 10 | 15×15 | 24–28 | 171–210 |

### Эталонные агенты

`spatial_harness_bench/maze/baselines.py` — рабочие адаптеры протокола: нижняя и верхняя границы для серии. Результаты на пяти seed (1–5):

| Агент | Память | Балл | Эффективность |
| --- | --- | ---: | ---: |
| `right-hand`, `left-hand` — рука на стене | нет | 0/10 | 0.00 |
| `random` — случайная открытая дверь | нет | 2.0/10 (95% ДИ 0.8…3.2) | 0.06 |
| `dfs` — обход в глубину с возвратом | полная | 10/10 | 0.29 |

```sh
uv run python -m spatial_harness_bench.maze --suite --seed 1 --output runs/maze-dfs -- \
  uv run python -m spatial_harness_bench.maze.baselines dfs
```

### Запуск

Для встроенного чат-адаптера задайте в окружении `OPENAI_BASE_URL` (включая `/v1`), `OPENAI_API_KEY` и `MODEL_ID`. Команда из корня репозитория запускает весь зачёт. Каждая задача получает отдельную сессию и пустую папку для заметок.

```sh
uv run python -m spatial_harness_bench.maze --suite --seed 8278864541757570430 \
  --output "runs/maze-v2-01/$MODEL_ID" -- \
  python3 "$PWD/scripts/maze_chat.py" --model "$MODEL_ID"
```

Для каждой найденной в пределах лимита комнаты с выходом начисляется один балл. По исчерпании лимита серия переходит к следующему уровню. При сбое адаптера серия останавливается со статусом `error` и пустым полем `score`. Журналы уже пройденных уровней сохраняются.

Для Pi используйте RPC-адаптер `python -m spatial_harness_bench.maze.pi -- <команда запуска Pi>`. Он открывает отдельную сессию на карту и передаёт наблюдения по одному. Команда запуска должна предоставлять инструментам Pi только папку заметок текущей карты. В официальном замере Pi работает в изолированной файловой системе. Исчерпание 32 ответов записывается в `result.json` как `reason="response_limit"` с номером хода.

Одинаковый `--seed` серии даёт всем моделям одинаковые десять карт. Без него раннер выбирает новый seed и записывает его в `suite.json`. Для отдельной задачи замените `--suite` на `--level 1` … `--level 10` и укажите новый каталог результата. Результаты версии 1 (`runs/maze-*`, задачи `02-maze-NN`) с версией 2 не сравнимы.

### Одиночная карта

Для свободного прогона доступны все целые размеры от 5×5 до 15×15 через `--size` (по умолчанию 10). Параметр `--loops` задаёт долю открытых дополнительных дверей: 0 — дерево версии 1, 0.15 — плотность зачёта. Сохранённые `size`, `seed` и `loops` из `result.json` позволяют повторить карту. Параметр `--limit` задаёт число разрешённых решений.

В `map.txt` символы `S` и `E` отмечают старт и выход, `#` — стену, `+` — закрытую дверь. В `steps.jsonl` записан каждый ход. Номер комнаты в журнале вычисляется как `строка × размер + столбец`, отсчёт с нуля. Модель во встроенном адаптере получает только инструкции, наблюдения и содержимое своих заметок.

### Подключение своего харнеса

После `--` можно передать команду другого адаптера. Раннер запускает один процесс в пустой рабочей папке на всю попытку. Обмен идёт по JSON Lines в UTF-8 через stdin/stdout. Первое сообщение содержит `instructions`. Каждое описание имеет поля `type="room"`, `turn` и `text`. На него адаптер возвращает одну строку, например `{"move":"вправо"}`, и сбрасывает буфер stdout. Игра заканчивается сообщением `type="end"` со статусом `solved` или `limit`. Диагностика адаптера идёт в stderr. Сбой адаптера записывается отдельно со статусом `error`.

Адаптер отвечает за инструменты, доступные модели. Встроенный вариант даёт ей только запросы к своим файлам в рабочей папке. Он передаёт историю диалога в Chat Completions и на длинных маршрутах удаляет старейшие полные ходы при превышении 180 000 символов сериализованной истории. Файлы сохраняются всю попытку и затем доступны в `notes/`. При подключении харнеса с shell запускайте модель в изоляции, где из данных прогона видна только её рабочая папка.

## 03 · Узнай свои SVG-рисунки

Модель рисует десять объектов реального мира в `0.svg` … `9.svg` и записывает простые русские названия по порядку в `desc.txt`. После рисования рабочая папка удаляется. В новом диалоге модель читает десять пронумерованных исходников SVG и восстанавливает названия по геометрии, цветам и расположению элементов.

| Набор объектов (`--objects`) | Что рисует модель |
| --- | --- |
| `free` (по умолчанию) | Десять объектов на свой выбор |
| `assigned` | Десять объектов, назначенных раннером по `--seed`, как в задаче 01 |
| `kitchen` | Пять из семи пар похожих кухонных предметов, например «сито и дуршлаг» или «чайник и кофейник», в единой чёрно-белой манере. При распознавании модель знает только тему |

Наборы `assigned` и `kitchen` не дают модели выбрать лёгкие объекты. Для сравнения моделей используйте один из них.

Правила подсчёта совпадают с задачей 01. Название, совпавшее с эталоном по правилам [сравнения ответов](#сравнение-ответов), даёт +1, ошибка или пустой рисунок — 0, подпись на любом языке — −1 даже при верном ответе. Итог за распознавание ограничен снизу нулём. До запуска распознавания проверяются текстовые узлы, XML-комментарии, описательные атрибуты и идентификаторы. Для видимых надписей, нарисованных контурами, применяется Tesseract с русским и английским словарями. Он ищет и эталонные названия, и их синонимы. OCR может пропустить стилизованную надпись или принять детали рисунка за буквы. Исходники сохраняются для просмотра. Рисунок с нарушением заменяется пустым SVG на той же позиции.

Поддерживаются автономные фигуры SVG, пути, группы, трансформации, заливки, обводки, линейные и радиальные градиенты, clipPath и inline style. Для внутренних ссылок подходят нейтральные идентификаторы вида `g1`. Для художника предпочтителен `viewBox`. Без него раннер использует размеры холста, по умолчанию 512×512. Скрипты, внешние ресурсы и встроенные растровые файлы не принимаются.

### Запуск с Codex

Пример для настроенного Codex CLI:

```sh
uv run --extra svg python -m spatial_harness_bench.svg_recall \
  --objects assigned --seed 1 --mode code --output runs/svg-example -- \
  python3 "$PWD/scripts/svg_codex.py" --model gpt-6.2-sol --effort medium
```

Встроенный адаптер передаёт исходники SVG текстом в порядке файлов. Он запускает отдельный `codex exec --ephemeral` на каждый этап и проверяет, что модель ответила без вызовов инструментов. Для другого харнеса после `--` укажите свою команду. Она получает промпт в stdin, рабочую папку со входами и переменные `SVG_RECALL_STAGE` (`draw` или `code`), `SVG_RECALL_DIFFICULTY` и `SVG_RECALL_COUNT` (число ответов). На каждом этапе адаптер сохраняет файлы из промпта в текущую папку. Адаптер отвечает за новый контекст и доступ к исходникам своего этапа. На этапе распознавания передавайте исходники текстом и отключите инструменты рендера и просмотра.

В каталоге результата исходники и эталон лежат в `original/`, отрисовки для проверки подписей и просмотра — в `rendered/`, сданные ответы — в `code/desc.txt`. В `result.json` поле `checks` хранит результаты проверки рисунков, а `modes.code` — оценку ответов.

### SVG с перемещениями предметов

Уровни `--difficulty hard`, `expert` и `master` используют те же десять авторских рисунков. Раннер размещает их на поле 4×4, шесть клеток остаются пустыми. Для каждого из десяти вопросов модель начинает с одного и того же исходного поля, мысленно выполняет команды и определяет, какой предмет попал в указанную конечную клетку. Ответ содержит исходную клетку и название предмета, например `2,3 | зонт`. Каждому рисунку соответствует один зачётный вопрос.

| Уровень | Операций по вопросам 1…10 | Как задаются операции |
| --- | --- | --- |
| `hard` | 2, 3, 4, 5, 6, 7, 8, 9, 10, 12 | Сдвиг указанной строки или столбца с переходом через край, поворот квадрата 2×2 или всего поля на 90° |
| `expert` | 4, 5, 6, 7, 8, 9, 10, 12, 14, 16 | Добавляются сдвиги и обмены линий по текущим положениям нескольких предметов |
| `master` | 8, 10, 12, 14, 16, 18, 20, 22, 25, 28 | Те же операции, что в `expert`, но цепочки вдвое длиннее |

Например, команда «сдвинь вправо строку с предметом из (3,2)» требует найти предмет, стоявший в (3,2) в начале вопроса. Если к этому шагу он оказался в первой строке, сдвигается первая строка. Генератор проверяет, что решение по неподвижным ориентирам даст другую исходную клетку.

Эти уровни измеряют отслеживание перестановок, поэтому **балл начисляется за верную исходную клетку** (`"scoring": "origin"`). Узнавание рисунка учитывается отдельно: `name_hits` — верные названия, `full_hits` — клетка и название вместе, `origin_hits` — верные клетки. Все три поля считаются среди допустимых рисунков. Подпись в авторском рисунке даёт −1 в вопросе про этот рисунок. Такой объект скрывается на поле. Итог ограничен диапазоном 0…10. До этого изменения балл требовал и клетку, и название: старые отчёты без поля `scoring` соответствуют нынешнему `full_hits`.

Одинаковые рисунки и seed воспроизводят поле и вопросы одного уровня. Модель получает исходник `board.svg` и вопросы. Копия поля `board.png` сохраняется для просмотра после прогона. Файлы поля, `questions.txt`, ответы и отчёт сохраняются после распознавания. Свой адаптер может определить уровень по `SVG_RECALL_DIFFICULTY`.

Пример повторного замера на рисунках модели из предыдущего прогона:

```sh
uv run --extra svg python -m spatial_harness_bench.svg_recall \
  --difficulty master --seed 42 --mode code \
  --drawings runs/svg-recall-01/codex-sol-6.2/original --output runs/svg-master-example -- \
  python3 "$PWD/scripts/svg_codex.py" --model gpt-6.2-sol --effort medium
```

Без `--drawings` модель сначала рисует в новой сессии. Без `--seed` раннер выбирает случайный seed и записывает его в `result.json`. Наборы `kitchen` и `assigned` работают на всех уровнях, поэтому один комплект рисунков можно проверить отдельно на узнавание и на перемещения.

## 04 · Вопросы по SVG-сценам

Все модели получают одинаковые сцены и вопросы. Задача участника — рассмотреть рисунок и ответить. Есть два набора.

### Набор `generated`: процедурные сцены

![Пример сгенерированного набора, seed 7](docs/svg-scenes-gen-v1.png)

Генератор (`spatial_harness_bench/svg_scenes/generated.py`) строит сцены из цветных фигур. Ключи верны по построению. Тесты независимо выводят каждый ключ из SVG-исходника: заново вычисляют геометрию, сшивают сегменты шнуров, раскрашивают перекрытия в порядке отрисовки и поворачивают карточку собственной реализацией. Четыре вида вопросов, у каждого три ступени сложности:

| Вид | Вопрос | Ступени 1 → 3 |
| --- | --- | --- |
| `count` | Сколько фигур заданного цвета и формы лежит целиком по одну сторону пунктирной линии. Отвлекающие фигуры совпадают по цвету или по форме, часть фигур пересекает линию | 10 → 16 → 24 фигуры, мельче |
| `occlusion` | Какая фигура лежит поверх A и сама частично закрыта B. Решают видимые пиксели, генератор выбирает пары, где каждая подсказка по отдельности неоднозначна | 5 → 8 → 11 фигур |
| `cords` | К розетке какого цвета ведёт шнур от прибора. В SVG-исходнике каждый шнур разрезан на сегменты, и сегменты перемешаны | 3 шнура и 3 пересечения → 5 и 7 → 7 и 12 |
| `transform` | Какие фигуры окажутся в двух клетках после поворотов и отражений карточки. Ответ отличается от ответов при неверных прочтениях: без преобразований, только с первой или последней командой, с командами в обратном порядке | 3×3 и 1 команда → 3×3 и 2 → 4×4 и 4 |

`--per-tier N` задаёт число вопросов на вид и ступень, по умолчанию 2: всего 24 вопроса. В `result.json` есть разбивка `by_kind` по видам и ступеням. Промпт перечисляет формы и цвета. В режиме `code` к цветам добавлены их hex-коды, чтобы ошибка именования цвета не смешивалась с пространственной ошибкой.

**Закрытый набор.** Seed полностью определяет сцены и ключи. Для публичного лидерборда организатор держит seed в секрете и публикует только баллы, `dataset_sha256` и версию генератора. Каталог результата содержит seed и сцены (`scenes/`), поэтому его не публикуют. Открытый seed подходит для отладки и воспроизведения.

```sh
uv run --extra svg python -m spatial_harness_bench.svg_scenes \
  --set generated --seed "$PRIVATE_SEED" --mode code --output runs/scenes-gen-example -- \
  python3 "$PWD/scripts/svg_codex.py" --model gpt-6.2-sol --effort medium
```

### Набор `fixed`: десять авторских сцен

Десять авторских иллюстраций подготовлены заранее. [Посмотреть всю серию](docs/svg-scenes-v1.png). Сцены и ключ лежат в открытом репозитории и могут попасть в обучающие данные моделей, поэтому набор подходит для демонстрации и отладки адаптера, а для рейтинга лучше брать `generated` с закрытым seed.

| Уровень | Задание |
|---:|---|
| 1 | Узнать отдельный предмет по форме |
| 2 | Узнать летательный аппарат по корпусу, подвеске и корзине |
| 3 | Назвать предмет слева от указанного |
| 4 | Найти предмет между двумя ориентирами |
| 5 | Найти предмет на полках по двум пространственным условиям |
| 6 | Посчитать объекты нужного цвета по одну сторону арки |
| 7 | Определить предмет по тому, что он перекрывает и что перекрывает его |
| 8 | Проследить шнур через два пересечения до розетки |
| 9 | Назвать два предмета после поворота и зеркального отражения карточки |
| 10 | Проследить две линии маршрута с пересадкой и назвать ориентиры по порядку |

Уровни упорядочены по замыслу автора. За полный ответ на вопрос начисляется 1 балл, максимум 10. Эталон включает распространённые синонимы, остальное покрывают правила [сравнения ответов](#сравнение-ответов). В вопросах 9 и 10 важен порядок обоих ответов.

```sh
uv run --extra svg python -m spatial_harness_bench.svg_scenes \
  --mode code --output runs/fixed-scenes-example -- \
  python3 "$PWD/scripts/svg_codex.py" --model gpt-6.2-sol --effort medium
```

### Общее для обоих наборов

Харнес передаёт исходные SVG в новый диалог. Адаптер получает вопросы в stdin, пронумерованные рисунки в рабочей папке и пишет по строке на вопрос в `desc.txt`. Ему доступны `SVG_RECALL_STAGE=code`, `SVG_RECALL_DIFFICULTY=fixed|generated` и `SVG_RECALL_COUNT`. Изолируйте собственный адаптер от репозитория с эталоном.

Для набора `fixed` перед прогоном общая проверка подписей анализирует XML и растры. При дефекте авторского рисунка запуск останавливается до оценки модели. В `result.json` сохраняются баллы по каждому вопросу и SHA-256 набора, включающий исходные SVG, вопросы и допустимые ответы. [Исходные сцены](spatial_harness_bench/svg_scenes/art/) · [Вопросы и ключ проверки](spatial_harness_bench/svg_scenes/items.json).

## 05 · Монтажный индекс

В задаче `05-arcade-clips` харнес получает игровой движок и журнал матча на 30 584 тика. Для каждого из 30 521 перекрывающихся клипов длиной 64 кадра нужно вычислить прирост очков двух игроков и построить бинарный индекс `clips.rix`. Второй файл, `query.py`, находит клип заданного ранга в диапазоне стартовых тиков. При равном приросте выше стоит более ранний клип.

За точный индекс и правильные ответы на всех трёх реплеях начисляется 1 балл. Каждый запрос запускает `query.py` в отдельном процессе. Программа получает страницы индекса через stdin/stdout и должна вернуть стартовый тик и прирост очков за 96 чтений и 5 секунд.

Запуск на Linux с Bubblewrap и системным Python 3.12. Адаптер харнеса получает условие через stdin и работает с файлами текущего каталога. Для замеров изолируйте его от исходников бенчмарка и эталонного решения.

```sh
python3 -m spatial_harness_bench.arcade_clips --output runs/arcade-clips-01 -- \
  claude -p --bare --no-session-persistence --strict-mcp-config \
  --tools Read,Write,Bash --allowedTools Read,Write,Bash
```

В каталоге результата сохраняются сданные файлы и отчёт `result.json` с оценкой.

## 06–10 · Поэтажные планы

Все пять задач относятся к одному пятиэтажному дому «Маяк». Каждый этаж занимает 6 × 5 клеток. Модель получает текстовые описания нужных этажей с диапазонами комнат и квартир в каждом ряду. Направления местных координат подписаны на каждом плане. Один номер на двух этажах обозначает двухуровневую квартиру.

| Задача | Вопрос |
| --- | --- |
| 06 · Сосед сверху | Какая квартира находится над заданным углом квартиры на первом этаже? |
| 07 · Стук в потолок | Какие квартиры непосредственно под спортзалом сложной формы услышат стук? По условию звук передаётся только вертикально вниз на один этаж. |
| 08 · Общая вертикаль | В каких клетках совпадают мастерская, серверная и диспетчерская на трёх этажах, если третий план размечен с востока на запад? |
| 09 · Прямой воздуховод | Какие вертикали через все пять этажей затронут минимум квартир и обойдут ядро и щитовую? Нужны все оптимальные клетки и минимум. |
| 10 · Воздуховод со смещением | Как соединить один из пяти вводов с одним из пяти выходов, сделав прямое смещение на третьем этаже? Сначала минимизируется число разных квартир на всей трассе, затем длина смещения. |

За полный правильный ответ даётся 1 балл. При проверке списков учитывается состав, порядок произвольный. Проверяющий вычисляет проекции и перебирает все допустимые трассы по планам дома. Серия даёт до **5 баллов** в общем лидерборде.

Каждое задание выполняется в отдельной сессии с инструментами чтения, записи и вычислений.

```sh
uv run python -m spatial_harness_bench.building --output runs/building-01 -- \
  claude -p --bare --no-session-persistence --strict-mcp-config \
  --tools Read,Write,Bash --allowedTools Read,Write,Bash
```

По умолчанию выполняются все пять задач. Опция `--level 1` … `--level 5` перед `--output` запускает одну. Каждый вызов харнеса получает условие через stdin и пустую рабочую папку для `answer.json`. При зачётном замере изолируйте инструменты харнеса от репозитория и прошлых ответов. В каталоге прогона сохраняются выданные условия, сданные файлы и общий `result.json` с проверкой по каждому заданию. Пустой или ошибочный ответ даёт 0. Отказ шлюза вызывает повтор с исходным условием. После исчерпания повторов общий балл остаётся неопределённым.

## Повторы и доверительные интервалы

Каждый прогон — одна выборка: случайный seed, одна сессия модели. Для сравнения моделей повторите прогон несколько раз с разными seed и сведите отчёты:

```sh
for seed in 1 2 3 4 5; do
  uv run --extra svg python -m spatial_harness_bench.svg_scenes --set generated --seed "$seed" \
    --mode code --output "runs/rep-$seed/sol" -- python3 "$PWD/scripts/svg_codex.py" --model gpt-6.2-sol
done
uv run python -m spatial_harness_bench.stats sol='runs/rep-*/sol' haiku='runs/rep-*/haiku'
```

Аргумент `LABEL=GLOB` собирает все `result.json` и `suite.json` под найденными каталогами. Файлы уровней внутри серии лабиринта не учитываются повторно. Отчёты группируются по метке, задаче и режиму. Таблица показывает:

- **Балл и 95% ДИ по прогонам** — t-интервал по итоговым баллам. Нужно не меньше двух прогонов. Это честный интервал для сравнения моделей: он учитывает разброс между seed и сессиями.
- **Долю верных и 95% ДИ по пунктам** — интервал Уилсона по всем пунктам вместе. Он считает пункты независимыми и поэтому уже. При одном прогоне это единственная оценка.
- **Эффективность** для лабиринта.

Флаг `--json` выводит то же в машиночитаемом виде.
